# 用户故事

版本：v1.0 · 状态：Draft · 最后更新：2026-08-09

用户故事按角色分组，优先级 `P0`（主线必须） / `P1`（延伸，3 周内如遇超支优先砍）。

## 角色

- **customer**：客户，提交工单、跟进、评价。
- **agent**：客服，处理工单、审阅 AI 建议、发送回复、维护知识库。
- **admin**：管理员，管理用户、知识库、审计日志。

---

## 1. customer（客户）

### 认证与账号

- [P0] 作为客户，我想注册一个账号（邮箱 + 密码），以便提交工单。
- [P0] 作为客户，我想登录系统，以便查看我的工单。
- [P0] 作为客户，我想退出登录，以便安全离开共享电脑。
- [P1] 作为客户，我想修改密码，以便在密码泄露时更换。

### 工单

- [P0] 作为客户，我想创建一张工单（标题 + 描述），以便报告问题。
- [P0] 作为客户，我创建工单时希望系统自动识别分类、摘要、优先级和情绪，以便我确认问题被正确理解。
- [P0] 作为客户，我想查看我的工单列表（分页），以便跟进处理进度。
- [P0] 作为客户，我想按状态筛选我的工单，以便只看未解决的。
- [P0] 作为客户，我想查看工单详情，以便了解 AI 分析结果和客服回复。
- [P1] 作为客户，我想在我的工单被处理前修改描述，以便补充信息。
- [P1] 作为客户，我想取消我自己还未被处理（`open`）的工单，以便撤销误提交（`open → canceled`）。
- [P1] 作为客服，我想取消处理中（`in_review`）但已确认无需继续的工单，以便关闭无效工单（`in_review → canceled`）。

### 回复与评价

- [P0] 作为客户，我想看到客服的回复和 AI 回复建议，以便了解处理方案。
- [P0] 作为客户，我想对已关闭的工单评分并评论，以便反馈服务体验。
- [P0] 作为客户，我只应能评价我自己提交且状态为 `closed` 的工单（`canceled` 工单不可评价），以便保证评价可信。

## 2. agent（客服）

### 工单处理

- [P0] 作为客服，我想查看全部工单列表（分页），以便按优先级处理。
- [P0] 作为客服，我想按状态 / 优先级 / 分类筛选工单，以便聚焦待处理项。
- [P0] 作为客服，我想打开工单详情，以便查看客户描述和 AI 分析结果。
- [P0] 作为客服，我想把工单置为 in_review，以便标记我正在处理。
- [P0] 作为客服，我想触发"生成回复建议"，以便获得基于知识库的草稿。
- [P0] 作为客服，我想审阅并编辑 AI 建议，以便确认内容准确后发送。
- [P0] 作为客服，我想发送回复，以便客户能收到处理方案。
- [P0] 作为客服，我想关闭已回复的工单，以便标记处理完成。
- [P0] 作为客服，我不能绕过 AI 建议直接自动发送未经审核的内容，以便保证合规。

### 知识库

- [P0] 作为客服，我想上传知识库文档（PDF/TXT），以便 RAG 能检索到相关资料。
- [P0] 作为客服，我想查看知识库文档列表及其处理状态，以便确认上传成功。
- [P0] 作为客服，我想删除不再有效的知识库文档，以便避免检索到过期内容。
- [P1] 作为客服，我想搜索知识库内容，以便人工确认建议的引用。

---

## 3. admin（管理员）

### 用户管理

- [P0] 作为管理员，我想创建 agent/admin 用户，以便分配账号。
- [P0] 作为管理员，我想查看用户列表并修改用户角色，以便管理团队权限。
- [P1] 作为管理员，我想停用某个用户账号，以便处理离职或滥用。

### 审计与治理

- [P0] 作为管理员，我想查看审计日志（操作者、动作、实体、时间），以便追溯操作。
- [P0] 作为管理员，我想按用户 / 动作 / 实体筛选审计日志，以便快速定位问题。
- [P0] 作为管理员，所有状态变化、回复、审核、删除操作都应被记录，以便审计留痕。
- [P1] 作为管理员，我想看到工单数量统计（总数 / 按状态 / 按优先级），以便了解团队负载。

### 知识库治理

- [P0] 作为管理员，我想删除失效知识库文档，以便维持知识库质量。
- [P1] 作为管理员，我想禁用某条知识库文档使其不再被检索，以便临时下线而不删历史。

## 4. 系统级用户故事（所有角色共同）

### 幂等与可靠性

- [P0] 作为系统，工单创建请求携带 Idempotency-Key 时，重复请求不产生重复工单。
- [P0] 作为系统，RQ 任务使用稳定业务 key，同一业务请求不会被重复处理。
- [P0] 作为系统，AI 处理失败时任务自动重试（基础重试），并记录错误到 ai_processing_jobs。

### 安全

- [P0] 作为系统，密码必须以 bcrypt 加密存储，不以明文落库。
- [P0] 作为系统，所有需要权限的接口必须校验 JWT 与角色，越权返回 403。
- [P0] 作为系统，API Key、数据库密码、个人真实资料不得进入 Git 仓库。

### 合规边界

- [P0] 作为系统，AI 只能生成分类结果和回复建议，不得直接发送回复。
- [P0] 作为系统，AI 所有输出必须经过 Pydantic schema 校验后才能入库。

---

## 验收备注

- 所有列表接口（工单、用户、审计、知识库文档）必须支持分页。
- 所有写操作（回复、审核、删除、状态转移）必须写入 `audit_logs`。
- 所有越权访问返回 `403 Forbidden`；未认证返回 `401 Unauthorized`。
- 非法状态转移返回 `409 Conflict`，并附当前状态和允许的操作。
